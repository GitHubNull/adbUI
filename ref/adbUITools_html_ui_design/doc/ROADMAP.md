# 功能规划路线图(Roadmap)

> 本文档为 adbUITools_html_ui_design(跨平台 PC 端 ADB 设备管理应用的 UI 前期设计探索项目)的后续优化参考指引,基于对主流搞机工具(参考标杆:晨钟酱《搞机工具箱》V11 等免 Root ADB 图形化工具)的对比分析整理。
> 文档状态:规划草案,优先级与范围可在实施过程中调整。

## 1. 背景与目标

**当前定位**:跨平台 PC 端 ADB 设备管理应用的 UI 前期设计探索,以纯前端静态页面(HTML/CSS/JS)呈现设计稿,无框架、无构建依赖,全部数据为内置演示数据(mock),不连接真实设备、无后端服务。

**参考标杆**:B 站 Up 主"晨钟酱"(承重墙)开发的《搞机工具箱》V11 —— 2017 年至今迭代 150+ 次的免 Root ADB 图形化工具,覆盖软件管理、显示调节、电池模拟、自动化脚本等深度控制能力。

**远期目标**:基于本项目的 UI 设计方案,采用跨平台桌面技术栈(Electron / Tauri 等)实现真实可用的跨平台 PC 应用,直接集成 ADB 能力,覆盖主流搞机工具的 80% 常用能力,保持"免 Root、跨平台"的桌面端优势。

| --- | --- | --- |
| 应用管理 | 列表查看、搜索、排序、安装 APK | ★★☆ |
| 文件管理 | 目录浏览、属性查看 | ★☆☆ |
| 日志查看器 | Logcat 实时滚动、级别过滤 | ★★★ |

| 命令历史 | 记录、搜索、复用 | ★★★ |

## 3. 差距分析

### 3.1 现有模块深度不足

| 模块 | 缺失能力 | 涉及 ADB 命令/原理 |
| --- | --- | --- |
| 应用管理 | 卸载/批量卸载、提取 APK、冻结/解冻、强制停止、清除数据/缓存、保留数据卸载 | `pm uninstall` / `pm uninstall -k` / `pm disable` / `am force-stop` / `pm clear`、`adb pull` 提取 |
| 文件管理 | push/pull 双向传输、批量传输、拖拽导入 | `adb push` / `adb pull` |
| Shell 终端 | 常用命令库、快捷指令、输出保存 | 预设命令模板库 |
| 性能监控 | 温度/帧率/GPU/功耗、报告导出 | `dumpsys battery`、`dumpsys gfxinfo` |

### 3.2 完全缺失的热门功能

**系统参数调节**(搞机工具箱招牌能力,免 Root 深度控制):
- 分辨率 / DPI 调节:`wm size` / `wm density`
- 过扫描边界:`wm overscan`
- 动画速度、字体大小、锁屏时间调节:`settings put global` 系列

**电池模拟**(测试向):
- 模拟电量 / 温度 / 充电状态:`dumpsys battery set level/temperature/status`

**界面定制**:
- 隐藏状态栏 / 导航栏、电池图标样式、刘海区域设置

**自动化脚本(控机)**:
- 自动点击 / 滑动 / 按键:`input tap` / `input swipe` / `input keyevent`
- 循环、延时、批处理脚本与宏录制回放

**进阶玩机**:
- Shizuku 集成(免 Root 更高权限)
- 重启到 Recovery / Bootloader / Fastboot
- 系统应用停用白名单、跳过广告、应用保活

**设备信息深度**:
- 硬件/系统详细报告:`getprop` + `dumpsys` 聚合展示

### 3.3 架构层面差距(根本原因)

| 差距 | 说明 | 解决方向 |
| --- | --- | --- |
| 无真实 ADB 执行引擎 | 全部操作停留在 mock,功能差距的根源 | 桌面应用中直接集成 ADB 能力(如 Electron 内嵌 adb 二进制或 Node adbkit),执行真实命令 |
| Web 沙箱限制 | 浏览器无法直接访问 adb server | 后期改为桌面应用(Electron / Tauri 等)后沙箱限制消失,可原生访问系统 adb |
| 缺少异步任务模型 | 批量操作需要进度、队列、结果回传 | 建立任务队列框架(任务 ID、进度事件、结果回调) |
| 无设备状态同步 | 无法感知设备在线/离线/授权状态 | 设备心跳轮询 + 事件推送 |

## 4. 功能规划(分优先级)

### P0 — 基建与基础增强(先让工具"能用")

| # | 功能 | 说明 | 验收标准 |
| --- | --- | --- | --- |
| 0.1 | ADB 引擎集成 | 在桌面应用中集成 ADB 能力(内嵌 adb 二进制或 Node adbkit),建立命令执行基础层 | 可在应用中执行 `adb devices` 并返回真实设备列表 |
| 0.2 | 设备生命周期管理 | 设备发现、连接/断开、授权状态展示与刷新 | 状态栏实时反映真实设备状态 |
| 0.3 | 异步任务框架 | 命令执行任务化:进度、取消、结果回传 | 批量操作(如批量安装)有进度条与结果汇总 |
| 0.4 | 应用管理增强 | 卸载、批量卸载、提取 APK、冻结/解冻、强制停止、清除数据 | 覆盖 `pm` 家族核心操作,含确认弹窗与结果反馈 |
| 0.5 | 文件传输 | push/pull 双向传输、批量传输、进度显示 | 支持拖拽文件上传至设备,下载保存到本地 |

### P1 — 玩机核心能力(对标搞机工具箱招牌功能)

| # | 功能 | 说明 | 验收标准 |
| --- | --- | --- | --- |
| 1.1 | 分辨率/DPI 调节 | 预设档位 + 自定义输入,支持恢复默认 | `wm size` / `wm density` 即时生效,失败有回滚提示 |
| 1.2 | 过扫描调节 | 四边边界无级调节,实时预览 | `wm overscan` 生效,提供重置 |
| 1.3 | 系统参数无级调节 | 动画速度(3 档+自定义)、字体大小、锁屏时间 | `settings put global` 系列封装,即时反馈 |
| 1.4 | 电池模拟 | 模拟电量/温度/充电状态,一键还原 | `dumpsys battery set/unset` 封装 |
| 1.5 | 重启模式 | 重启系统 / Recovery / Bootloader / Fastboot | `adb reboot` 系列,带二次确认 |
| 1.6 | 按键与输入模拟 | 点击、滑动、长按、物理按键 | `input` 系列封装,支持坐标与相对位置 |
| 1.7 | 自动化脚本 | 录制/编辑/执行脚本(点击、滑动、延时、循环) | 支持脚本文件导入导出与执行中停止 |
| 1.8 | 常用命令库 | 高频 ADB 指令一键执行,可收藏自定义 | 命令库分类管理,与命令历史联动 |

### P2 — 生态与进阶(差异化竞争力)

| # | 功能 | 说明 | 验收标准 |
| --- | --- | --- | --- |
| 2.1 | 设备信息报告 | 硬件/系统/网络/电池信息聚合,支持导出 | `getprop` + `dumpsys` 数据可视化呈现 |
| 2.2 | 界面定制 | 隐藏状态栏/导航栏、电池样式、刘海设置 | 系统界面类 `settings`/`wm` 命令封装 |
| 2.3 | Shizuku 集成 | 通过 Shizuku 获取更高权限执行受限操作 | 连接状态可视化,受限命令白名单引导 |
| 2.4 | 屏幕投屏 | 集成 scrcpy/Web 投屏方案 | 浏览器内实时查看设备画面 |
| 2.5 | 应用保活与广告跳过 | 保活白名单、电视盒子跳过广告 | 常用包名单模板 + 自定义 |
| 2.6 | 设置模块落地 | ADB 路径、主题、语言、默认参数配置 | 配置持久化(localStorage) |

## 5. 实施约束与原则

1. **设计稿与实现分离**:当前阶段保持纯前端零依赖约束,仅产出 UI 设计方案;后期实现基于跨平台桌面技术栈(Electron / Tauri 等),直接集成 ADB 能力,不做浏览器桥接方案
2. **安全优先**:所有设备操作需明确确认;危险命令(擦除、格式化、解锁 BL)需二次确认 + 警示说明
3. **渐进式落地**:P0 完成前不扩展新模块;每个功能先"假数据 UI"再"接真实引擎",避免 UI 返工
4. **文档同步**:每个里程碑完成后更新本文档状态与 README 功能清单
5. **架构兼容**:新增功能优先复用既有 `renderXxx()` + `initXxx()` 模式与设计令牌,保持代码规范一致(见 AGENTS.md)

## 6. 里程碑建议

| 里程碑 | 范围 | 预期效果 |
| --- | --- | --- |
| M1 基础可用 | P0 全部 | 从演示 UI 变为"能连真机"的可用桌面应用 |
| M2 玩机核心 | P1 全部 + P2 部分 | 对标搞机工具箱核心体验,形成差异化 |
| M3 生态扩展 | P2 剩余 | 完整覆盖主流搞机场景,输出正式版本 |

> M2 玩机核心详细实施规划(功能清单、验收标准、mock 实现路径与真实 ADB 引擎过渡方案)见 [doc/M2_PLAY_CORE_PLAN.md](doc/M2_PLAY_CORE_PLAN.md)
